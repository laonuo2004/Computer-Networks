# Reliable File Transfer using Go-Back-N Protocol

This project implements reliable file transfer over UDP using the Go-Back-N protocol. It uses a self-defined PDU format, CRC-CCITT-FALSE checksum, sender window control, receiver-side ordered delivery, timeout retransmission, configurable PDU loss/corruption, communication logs, and a log analysis program.

The default configuration runs a local full-duplex transfer between Host1 and Host2. Host1 sends `data/host1.bin` to Host2, and Host2 sends `data/host2.bin` to Host1 at the same time.

## Project Structure

```text
.
|-- gbn/                    # protocol implementation
|   |-- pdu.py              # PDU format, CRC, encode/decode
|   |-- host.py             # UDP host, sender, receiver, Go-Back-N logic
|   |-- channel.py          # simulated PDU loss and corruption
|   |-- logging_utils.py    # CSV communication log writer
|   `-- analyzer.py         # log statistics and SVG chart generation
|-- configs/                # JSON configuration files for Host1 to Host4
|-- data/                   # input test files
|-- received/               # received output files
|-- logs/                   # CSV logs generated by transfer runs
|-- results/                # log analysis results
|-- tests/                  # unit tests
|-- generate_test_file.py   # deterministic binary test file generator
|-- run_demo.py             # local two-host full-duplex demo
|-- run_host.py             # run one host from a JSON config file
|-- analyze_logs.py         # analyze CSV logs
`-- README.md
```

## Environment

Recommended environment:

- Windows 10 or later
- Python 3.10 or later
- uv, used to create the Python virtual environment

The runtime program uses Python standard library modules. There is no `requirements.txt` file for this project.

Create and activate the virtual environment in PowerShell:

```powershell
uv venv
.\.venv\Scripts\Activate.ps1
```

If the activation script is generated under `bin` on your machine, use:

```powershell
.\.venv\bin\Activate.ps1
```

Check Python:

```powershell
python --version
```

## Generate Test Files

The submitted source package already contains test files in `data/`. If they need to be regenerated, run:

```powershell
python generate_test_file.py data\host1.bin
python generate_test_file.py data\host2.bin --seed 202
```

## Run the Local Full-Duplex Demo

Run:

```powershell
python run_demo.py --clean
```

Expected output:

```text
data/host1.bin -> received/from_host1.bin: OK
data/host2.bin -> received/from_host2.bin: OK
```

The `--clean` option removes old `logs/`, `received/`, and `results/` before the demo starts.

## Configuration

Each host is configured by a JSON file in `configs/`. Important fields include:

```text
host_id       host name used in logs
local_ip      local UDP IP address
local_port    local UDP port
data_size     maximum DATA field size in one PDU, no more than 4096 bytes
seq_bits      sequence number bits
sw_size       sender window size
init_seq_no   initial sequence number
timeout_ms    sender timeout in milliseconds
error_rate    simulated PDU corruption rate, in percent
lost_rate     simulated PDU loss rate, in percent
log_dir       CSV log output directory
receive_dir   received file directory
peers         peer hosts and file paths
```

For Go-Back-N sequence number safety, `sw_size` must be smaller than the sequence number space `2 ** seq_bits`. The program checks this condition during startup.

The sender and receiver should use the same `init_seq_no` setting. The default configuration files already use matching values.

## Multi-Host Run

The default configuration also contains Host3 and Host4. To run a multi-host experiment, open four PowerShell windows and start:

```powershell
python run_host.py configs\host1.json
python run_host.py configs\host2.json
python run_host.py configs\host3.json
python run_host.py configs\host4.json
```

Host1 can send the configured file to Host2, Host3, and Host4 at the same time when the peer settings are enabled in the JSON configuration files.

## Build the Windows Executable

The executable package is built on Windows with PyInstaller. The executable file name follows the required format:

```text
1120231863ReliableFileTransfer.exe
```

In PowerShell, enter this source directory first, then create and activate the uv environment:

```powershell
uv venv
.\.venv\Scripts\Activate.ps1
```

Install PyInstaller:

```powershell
uv pip install pyinstaller
```

Build the executable from the unified entry file:

```powershell
pyinstaller --onedir --name 1120231863ReliableFileTransfer gbn_transfer.py
```

PyInstaller creates the executable folder:

```text
dist\1120231863ReliableFileTransfer\
```

The program reads configuration and data files by relative paths, so the following folders should be copied into the executable folder:

```powershell
Copy-Item configs dist\1120231863ReliableFileTransfer\configs -Recurse -Force
Copy-Item data dist\1120231863ReliableFileTransfer\data -Recurse -Force
Copy-Item logs dist\1120231863ReliableFileTransfer\logs -Recurse -Force
Copy-Item results dist\1120231863ReliableFileTransfer\results -Recurse -Force
Copy-Item received dist\1120231863ReliableFileTransfer\received -Recurse -Force
```

A short README for executable users should also be placed in the same folder:

```text
dist\1120231863ReliableFileTransfer\README.txt
```

The final executable package should have this structure:

```text
1120231863ReliableFileTransfer\
|-- 1120231863ReliableFileTransfer.exe
|-- _internal\
|-- configs\
|-- data\
|-- received\
|-- logs\
|-- results\
`-- README.txt
```

Test the executable in PowerShell:

```powershell
cd dist\1120231863ReliableFileTransfer
.\1120231863ReliableFileTransfer.exe --help
.\1120231863ReliableFileTransfer.exe demo --clean
.\1120231863ReliableFileTransfer.exe analyze --log-dir logs --output-dir results
```

The demo should print:

```text
data/host1.bin -> received/from_host1.bin: OK
data/host2.bin -> received/from_host2.bin: OK
```

Because the executable depends on the folders above, it is submitted as a folder-style Windows executable package instead of a single standalone file. The folder can be compressed as:

```powershell
Compress-Archive -Path 1120231863ReliableFileTransfer -DestinationPath 1120231863ReliableFileTransfer-Windows.zip -Force
```
